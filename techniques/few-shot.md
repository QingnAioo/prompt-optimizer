# Few-shot Prompting

## 概述

通过在 prompt 中提供少量高质量示例，引导模型理解期望的输入-输出模式。

## 核心原则

1. **示例质量 > 数量** — 2-3 个精选示例通常优于 5+ 个普通示例
2. **覆盖多样性** — 示例应覆盖不同情况，包括边界案例
3. **格式一致性** — 所有示例必须遵循完全相同的格式
4. **难度递进** — 从简单到复杂排列示例

## 模板

### 基础 Few-shot
```
[任务说明]

示例 1：
输入：[input_1]
输出：[output_1]

示例 2：
输入：[input_2]
输出：[output_2]

示例 3：
输入：[input_3]
输出：[output_3]

现在请处理：
输入：[actual_input]
输出：
```

### 带标签的 Few-shot（分类任务）
```
将以下文本分类为：正面 / 负面 / 中性

文本："这个产品质量超出预期！"
分类：正面

文本："包装有点破损，但产品本身还行"
分类：中性

文本："完全无法使用，浪费钱"
分类：负面

文本："[用户实际输入]"
分类：
```

### 带解释的 Few-shot
```
[任务说明]

示例 1：
输入：[input_1]
分析：[reasoning_1]
输出：[output_1]

示例 2：
输入：[input_2]
分析：[reasoning_2]
输出：[output_2]

现在请处理：
输入：[actual_input]
分析：
输出：
```

## 适用场景

- 输出格式要求严格
- 分类和标注任务
- 风格迁移和模仿
- 结构化数据生成

## 注意事项

- 避免示例中引入偏见（如全是正面分类的示例）
- 示例过长会占用 context window
- 如果任务定义足够清晰，zero-shot 可能已经够用
