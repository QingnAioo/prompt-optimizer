# Structured Output

## 概述

通过明确定义输出格式（JSON、表格、XML 等），确保模型输出可被程序解析和下游处理。

## 模板

### JSON 输出
```
[任务描述]

请严格按照以下 JSON 格式输出，不要添加任何额外文本：

{
  "field_1": "string - 字段说明",
  "field_2": number,
  "field_3": ["array item"],
  "field_4": {
    "nested_field": "说明"
  }
}

注意：
- 所有字符串值使用双引号
- 不要输出 markdown 代码块标记
- 如果某字段无信息，使用 null 而非省略
```

### 表格输出
```
[任务描述]

请以 Markdown 表格格式输出，包含以下列：

| 列名1 | 列名2 | 列名3 | 列名4 |
|-------|-------|-------|-------|
| (数据) | (数据) | (数据) | (数据) |

要求：
- 至少输出 [N] 行数据
- [列名1] 按 [排序规则] 排列
- 每个单元格不超过 [M] 个字
```

### 固定段落结构
```
[任务描述]

请严格按照以下结构输出：

## 标题
[一句话总结]

## 背景
[2-3 句话描述背景]

## 要点
- 要点1：[说明]
- 要点2：[说明]
- 要点3：[说明]

## 结论
[一段话结论]

## 下一步行动
1. [行动项1]
2. [行动项2]
```

### XML/标签式输出
```
[任务描述]

请使用以下 XML 标签格式输出：

<result>
  <summary>一句话摘要</summary>
  <details>
    <point importance="high|medium|low">要点内容</point>
    ...
  </details>
  <recommendation>建议</recommendation>
</result>
```

## 最佳实践

1. **提供完整 schema** — 不要只说"输出 JSON"，要给出完整结构
2. **标注字段类型** — 明确 string/number/boolean/array
3. **给出示例值** — 用具体示例值代替抽象描述
4. **处理边界** — 说明缺失数据如何表示
5. **限制嵌套** — 嵌套不超过 3 层

## 适用场景

- API 集成
- 数据提取和结构化
- 自动化流程中间步骤
- 需要程序解析输出的场景

## 注意事项

- 配合 JSON mode（如 OpenAI 的 response_format）使用效果更好
- 过于复杂的 schema 可能降低遵循率
- 可以用 few-shot 示例强化格式约束
